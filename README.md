# La Cucina (by aml badr)

متجر إلكتروني مبني بـ React.js + Vite + Tailwind CSS، بأربع صفحات منفصلة.

```
src/
├── pages/
│   ├── Home.jsx           # الصفحة الرئيسية — بتعرض "المنتجات" بس
│   ├── ProductDetail.jsx  # صفحة وصف المنتج (/product/:id) — وتحتها "العروض"
│   ├── Cart.jsx           # صفحة عربة التسوق (/cart)
│   └── Checkout.jsx       # صفحة الدفع (/checkout)
├── components/            # مكونات مشتركة (Navbar, Footer, ItemCard, ProductGallery...)
├── context/
│   ├── CatalogContext.jsx # بيوزّع المنتجات والعروض على كل الصفحات
│   └── CartContext.jsx    # حالة السلة (Context API + useReducer)
├── data/
│   ├── catalog.js         # كل المنتجات والعروض — الملف الوحيد اللي تعدّليه لإضافة/تغيير حاجة
│   └── products.js        # ثوابت عامة بس (المحافظات، تنسيق السعر)
└── App.jsx
```

## إضافة أو تعديل منتج / عرض

الملف الوحيد اللي محتاجة تفتحيه هو **`src/data/catalog.js`**:

```js
export const PRODUCTS = [
  {
    id: "grease-remover",
    name: "مزيل الدهون القوي",
    price: 149,
    oldPrice: null,
    description: "وصف المنتج هنا...",
    images: ["/images/grease-remover-1.webp", "/images/grease-remover-2.webp"],
  },
  // ...أضيفي عنصر جديد هنا بنفس الشكل
];

export const BUNDLES = [
  {
    id: "kitchen-offer",
    name: "عرض المطبخ النظيف",
    price: 399,
    oldPrice: 550,
    description: "وصف العرض هنا...",
    images: ["/images/kitchen-offer-1.webp"],
  },
  // ...أضيفي عرض جديد هنا بنفس الشكل
];
```

- كل عنصر جوه `PRODUCTS` بيظهر في **الصفحة الرئيسية**.
- كل عنصر جوه `BUNDLES` بيظهر كـ"عرض" تحت وصف أي منتج في **صفحة المنتج**.
- **أول صورة في `images`** هي الصورة الرئيسية اللي بتظهر في الكارت وأعلى
  المعرض؛ باقي الصور بتظهر كصور مصغّرة قابلة للنقر في صفحة المنتج.
- لإضافة منتج أو عرض جديد: انسخي أي عنصر موجود جوه نفس المصفوفة، غيّري
  بياناته، واحفظي الملف — هيظهر على الموقع تلقائيًا من غير أي تعديل في
  باقي الكود.
- لو الوصف فيه سطر سعر (زي "سعر العبوة 149 ج.م")، اكتبي فيه `{price}`
  و`{oldPrice}` بدل الأرقام، عشان الرقم يتحدّث تلقائيًا لو غيّرتِ حقل
  `price`/`oldPrice` بتاع نفس المنتج. ولو فيه سطر عرض تاني منفصل (زي
  "2+1 مجانا")، استخدمي حقلي `priceOffer`/`oldPriceOffer` بنفس الطريقة
  مع `{priceOffer}`/`{oldPriceOffer}` في الوصف. تفاصيل أكتر تحت في قسم
  "ربط بيانات المنتجات بجوجل شيت".

### الصور

الصور متخزنة جوه المشروع في `public/images/` وبنشير لها بمسار نسبي زي
`/images/grease-remover-1.webp`. لإضافة صورة منتج جديد:
- ارفعيها في `public/images/`، أو
- استخدمي رابط صورة مستضافة على الإنترنت مباشرة في حقل `images` (لازم
  يبدأ بـ `http` أو `https`).

## ربط بيانات المنتجات بجوجل شيت (اختياري)

ده بيخلّيكِ تغيّري **الاسم، الفئة، السعر، السعر القديم، سعر العرض
التاني (زي 2+1) وسعره القديم، والوصف** لأي منتج أو عرض من جوجل شيت
مباشرة — من غير ما تفتحي الكود خالص. **الصور بتفضل زي ما هي دايمًا جوه
`catalog.js`** (زي ما طلبتِ، عشان الصور بتاخد مساحة وأصعب في النقل).

**ليه الطريقة دي آمنة:** الرابط اللي الموقع بيقرا منه بيانات المنتجات
هو رابط **قراءة فقط** (read-only) — مفيش أي طريقة إن حد يعدّل بيه
البيانات حتى لو عرفه أو فتحه في المتصفح. التعديل الفعلي بيحصل جوه جوجل
شيت نفسه، وده بيحتاج تسجيل دخول بحساب جوجل له صلاحية تعديل على الشيت
تحديدًا. يعني اللي يقدر يغيّر السعر هو بس اللي عنده صلاحية على الشيت،
مش أي حد شايف رابط الموقع.

### خطوات الإعداد

1. اعملي جوجل شيت جديد، وحطي الأعمدة دي بالظبط في أول صف (الأسماء
   لازم تكون بالظبط زي ما هي، بالإنجليزي):

   | id | name | category | price | oldPrice | priceOffer | oldPriceOffer | description |
   |----|------|----------|-------|----------|------------|----------------|--------------|

2. **عمود `id` هو الأهم** — لازم يتطابق حرفيًا مع الـ `id` بتاع نفس
   المنتج في `src/data/catalog.js` (زي `product-1`، `offer-2`... إلخ)،
   عشان الموقع يعرف يربط سعر/اسم الشيت بصورة المنتج الصح. لو الـ id في
   الشيت مش موجود أصلاً في `catalog.js`، الصف ده هيتجاهل.

3. املي صف لكل منتج عايزة تتحكمي فيه. **مش لازم تملي كل الأعمدة** —
   لو سبتِ خلية فاضية (زي `oldPrice` مثلًا)، الموقع هيفضل مستخدم القيمة
   المحلية من `catalog.js` لنفس الحقل ده.

   - لو عايزة تكتبي وصف بأسطر متعددة جوه خلية واحدة، استخدمي `|` بدل
     السطر الجديد، وهو هيتحول لسطر جديد تلقائيًا على الموقع. مثال:
     `أهم المميزات: | يشيل الدهون بسرعة | آمن على الأسطح`

   - لو وصف المنتج فيه سطر "سعر العبوة" (الاختيار الأساسي، مش أي عرض
     زي 2+1)، اكتبي فيه `{price}` و`{oldPrice}` بدل الأرقام مباشرة،
     مثال: `سعر العبوة {price} ج.م بدل {oldPrice} ج.م`. بكده لو غيّرتِ
     عمود `price`/`oldPrice` في نفس الصف، الرقم في الوصف والاختيار
     اللي بيظهر في صفحة المنتج هيتحدّث تلقائيًا معاه من غير ما تحتاجي
     تعدّلي رقمين في مكانين مختلفين.

   - نفس الفكرة بالظبط لأي عرض تاني منفصل في الوصف (زي "2+1 مجانا")،
     بس هنا استخدمي عمودي `priceOffer`/`oldPriceOffer` وحطي
     `{priceOffer}`/`{oldPriceOffer}` جوه الوصف بدل الأرقام، مثال:
     `2 + 1 مجانا {priceOffer} ج.م بدل {oldPriceOffer} ج.م`. ده سعر
     منفصل فعليًا عن سعر القطعة العادية (`price`)، فمحتاج عموده
     الخاص بيه بدل ما يتخلط مع سعر العبوة الواحدة.

4. من زرار **Share** (أعلى يمين الشيت):
   - في **General access**، اختاري **Anyone with the link**، وخليها
     **Viewer** (قراءة فقط — ده كافي، مش محتاجة "Editor").
   - دوسي **Done**. (مفيش داعي لـ File → Publish to web خالص — الطريقة
     دي بتقرا من الشيت اللايف مباشرة).

5. جيبي **معرّف الشيت (Sheet ID)** من رابط الشيت نفسه في المتصفح، وهو
   الجزء الطويل بين `/d/` و`/edit`:

   ```
   https://docs.google.com/spreadsheets/d/1-gAztJ87nmoRZyVSZK402aFFykTMnKj2GPOwVAI1-nw/edit
                                          └──────────── ده الـ Sheet ID ────────────┘
   ```

6. افتحي `src/data/remoteCatalog.js` والصقي المعرّف ده مكان
   `PASTE_YOUR_SHEET_ID_HERE`، وتأكدي إن `SHEET_TAB_NAME` مطابق لاسم
   التاب (الورقة) اللي فيها بيانات المنتجات (تحت في أسفل الشيت):

   ```js
   const SHEET_ID = '1-gAztJ87nmoRZyVSZK402aFFykTMnKj2GPOwVAI1-nw';
   const SHEET_TAB_NAME = 'Sheet1';
   ```

7. احفظي، وارفعي التحديث. من دلوقتي أي تعديل تعمليه في الشيت (وتحفظيه)
   بيوصل للموقع فورًا تقريبًا، لأن الطريقة دي بتقرا من الشيت اللايف
   مباشرة — من غير أي نسخة وسيطة أو خطوة "نشر" بتتأخر أو تتجدد كل شوية
   دقايق زي الطريقة القديمة.

**ملاحظة:** طول ما الرابط لسه فيه `PASTE_YOUR_...`، الموقع هيتجاهل
الخطوة دي تمامًا ويشتغل بالبيانات المحلية في `catalog.js` عادي —
فمفيش أي داعي تعمليها لو مش محتاجاها.

## التشغيل محليًا

```bash
npm install
npm run dev
```

سيعمل الموقع على `http://localhost:5173`.

## البناء للإنتاج

```bash
npm run build
```

## تخصيص الألوان

كل ألوان الهوية موجودة في مكان واحد: `tailwind.config.js` →
`theme.extend.colors.brand`.
